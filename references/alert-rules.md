# 趋势预警规则库

## 1. 九条规则

| # | 规则 | 判据 | 级别 | 类型 | 建议动作 |
|---|---|---|---|---|---|
| R1 | 月消费断崖 | 单月环比 ≤ −30% 且当月 < 均值×85% | P0 | 流失 | 48h 定位断崖原因（资源释放/项目结束/竞品替换），测算影响并给补救方案 |
| R2 | 连续下滑 | 连续 ≥3 月环比为负且累计 ≤ −15% | P1 | 流失 | 拆用量结构，找出流失品类，对下降品类做专项保留 |
| R3 | 同比下滑 | 窗口同比 ≤ −20% | P1 | 流失 | 对比去年同期项目结构，区分一次性项目与结构性流失 |
| R4 | 续约高危 | 到期 ≤90 天 且 风险分 ≥55 | P0 | 流失 | 启动高层续约对话，备竞品对比与商务让步，锁意向书 |
| R5 | 活跃断流 | MAU 近 3 月均值 ≤ 前 3 月 × 50% | P0 | 流失 | 排查账号/权限/项目变更，48h 触达确认是否切走 |
| R6 | 负面舆情抬头 | 平滑负面占比 ≥60% 且近 3 月样本 ≥3 条 | P1 | 流失 | 针对首要痛点出整改承诺与时间表，必要时升级服务等级 |
| R7 | 统计异动 | \|z\| ≥ 2（对前 6 月均值与标准差） | z>0 → P2 | 增长 / 流失 | 核实异动来源，真实变化则更新预测与资源规划 |
| R8 | 配额饱和 | 近 3 月使用率均值 ≥90% | P1 | 增长 | 提前出扩容方案（叠加节省计划降单价），把风险变增购 |
| R9 | 加速增长 | 同比 ≥ +30% 且 使用率 ≥60% | P2 | 增长 | 纳入重点增长名单，配专属资源承接增量，同步谈包年 |
| R10 | 试用激增 | 近 3 月试用 ≥3 次且窗口消费 = 0 | P2 | 增长 | 快速识别试用场景，48h 跟进转正方案 |

已流失客户不再触发预警（由 WINBACK 机会承接），避免同一事实重复报两次。

## 2. 响应 SLA

| 级别 | 含义 | 响应时效 | 责任人 |
|---|---|---|---|
| **P0** | 已经在发生、影响当期收入 | 48 小时内动作 | 客户经理 + 客户成功 + 主管知会 |
| **P1** | 正在恶化，需本周干预 | 一周内 | 客户经理 |
| **P2** | 信号级，纳入复盘 | 月度经营会 | 客户经理 |

## 3. 证据写法

每条预警必须带**可复核的时序**，例如：

```
单月环比 −32%；近6月 01=1,847,203、02=1,795,441、03=1,602,338、04=1,218,904…
```

没有时序数字的预警等于拍脑袋，报告里会被追问到无法回答。

## 4. 调参

`config.json`：

```json
"alert_z_threshold": 2.0
```

- 客户数少、波动大时，把 z 阈值提到 2.5，减少噪声；
- 想把「配额饱和」当增长机会重点抓，可下调 R8 的 90% 阈值（需改代码常量）；
- R1 的 −30% 与 R2 的 −15%，按业务季节性调整：有季节性行业建议先做同比再判环比。

## 5. 误报处理清单

| 误报 | 原因 | 处理 |
|---|---|---|
| 春节/财年结束导致单月暴跌 | 季节性 | 先看同比，同比正常则降级为 P2 |
| 一次性大项目结束 | 项目型客户 | 这类客户应改用「项目型」口径，不按月度趋势判断 |
| 资源数骤降但消费未降 | 规格升级/合并计费 | 只作提示，不进 P0 |
| 新签客户「连续下滑」 | 爬坡期波动 | tenure ≤6 月的客户不触发 R2 |
