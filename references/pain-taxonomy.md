# 痛点评分模型（分类法、优先级算法、证据要求）

## 1. 十个痛点域

| 痛点域 | 典型关键词 | 可行动性先验 | 默认建议动作 |
|---|---|---|---|
| 价格与成本 | 价格、贵、成本、折扣、报价、账单、超支、预算、性价比 | 0.85 | TCO 对比 + 节省计划/资源包测算，阶梯折扣换承诺消费 |
| 性能与稳定性 | 慢、卡、延迟、抖动、丢包、宕机、故障、超时、限流、带宽 | 0.80 | 联合 SRE 做架构与容量复盘，出优化清单 + SLA 保障说明 |
| 服务响应与支持 | 响应慢、工单、支持、客服、不及时、没人管、售后、SLA | 0.90 | 升级服务等级（企业支持/专属 TAM），补齐响应承诺 |
| 产品能力缺口 | 不支持、缺少、没有这个功能、无法满足、不兼容 | **0.40** | 产品经理评估需求，给路线图时间点或等价替代，**不空口承诺** |
| 文档与上手体验 | 文档、教程、指引、上手、学习成本、示例、难用、配置繁琐 | 0.85 | 场景化最佳实践 + 迁移指南 + 专场培训 |
| 生态与集成 | 生态、集成、对接、SDK、中间件、适配、集成难 | 0.55 | SA 做集成验证（POC），提供 SDK 与 ISV 资源 |
| 合规与安全 | 合规、等保、密评、审计、资质、数据出境、信创 | 0.70 | 输出合规矩阵与资质清单，推动安全方案立项 |
| 账号与权限 | 权限、账号、登录失败、子账号、IAM、配额申请 | 0.80 | 梳理 IAM 权限模型，提供一次性配置服务 |
| 计费与合同 | 合同、开票、发票、结算、账期、欠费、续订流程 | 0.75 | 对齐账单口径与商务条款，前置续约谈判节奏 |
| 迁移与切换成本 | 迁移、切换、割接、改造、迁云、迁移成本 | 0.50 | 迁移工具链 + 迁移服务报价，分批迁移降风险 |

分类优先级：**已有 `category` 字段可信就用它**（做模糊对齐）→ 否则关键词命中数最多的域 →
都没命中归入「其他/未归类」（报告里不进入共性结论，只在附录提示补齐字段）。

## 2. 五个评分维度

| 维度 | 权重 | 定义 | 归一化 |
|---|---|---|---|
| 提及广度 breadth | 30% | 提及该域的客户数 / 总客户数 | 直接 0~1 |
| 情感强度 intensity | 20% | 该域反馈的平均负向强度 `mean(-sentiment)` | 截断 0~1 |
| 金额暴露 exposure | 25% | 提及客户在窗口内的消费合计（无消费则取流失金额） | 组内分位 0~1 |
| 严重度 severity | 15% | `0.75×平均 severity + 0.25×升级比例`；severity 支持 P0-P3/高中低/1-5 | 0~1 |
| 可行动性 actionability | 10% | 该域的可解性先验；文本含「希望/建议/要求/需要/计划」再加 0.15 | 截断 0~1 |

`priority_score = 100 × Σ(权重 × 维度)`；**P0 ≥ 70，P1 50~70，P2 < 50**。

## 3. 共性 vs 个案

- **共性诉求**：提及客户数 ≥ 2 或 广度 ≥ 20%。可以进公司级结论、进产品需求池。
- **个案**：单客户单点问题。只随客户清单交付，**不要写成「客户普遍反映」**——这是最常见的夸大错误。

## 4. 证据要求

报告中每条痛点必须带：

1. **量化事实**：几家客户提及、覆盖多少收入、评分多少；
2. **一条原文引用**（≤110 字，保留原始措辞），用于交叉验证；
3. **建议动作**，且动作要能落到某个角色（客户经理 / SA / 产品 / 服务）。

挑选引用原文的规则：严重度 ×2 + 负向强度 + 信息量（长度，上限 120 字），取最高分。
对涉及具体个人的抱怨，引用时必须脱敏（去掉人名、工号、手机号）。

## 5. 情感解析口径（重要）

若源数据没有 `sentiment` 字段，用「词典 × 渠道先验」估算：

```
sentiment = 0.6 × 文本词典分 + 0.4 × 渠道先验
渠道先验：流失原因 −0.85｜投诉 −0.60｜工单 −0.35｜公开舆情 −0.35
          社区 −0.30｜销售拜访 −0.20｜NPS 调研/问卷/回访 −0.15｜其他 0
```

有字段时按刻度换算：`-1~1` 直接用；`1~5` → `(v-3)/2`；`0~10` → `(v-5)/5`；`正/中/负` → `±0.6/0`。

**这条链路引入的偏差必须在报告里承认**：估算的情感只用于「域间排序」，不能用来断言客户满意度水平。

## 6. 常见误判与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 「价格」永远排第一 | 几乎每家都会提折扣，广度天然最高 | 价格类痛点要看**是否伴随流失/降配动作**，否则只算「商务噪音」，在报告里降一档描述 |
| 单个大客户把某域顶到 P0 | 金额暴露维度被单客户主导 | 看 `account_count`：≤1 家时不当共性结论 |
| 工单类反馈全判负 | 渠道先验偏负 | 这是设计意图；若需中性口径，改用 NPS/调研数据源单独统计 |
| 某域突然消失 | 上期没有反馈数据 | 先查数据完整性，再谈改善 |
