# 机会点识别与打分模型

## 1. 四个维度（每维 0~100）

### 交叉销售潜力 cross_sell（权重 30%）
```
同业渗透率 pen(p) = 同行业客户中已采购品类 p 的客户数 / 同行业有消费客户数
缺口品类 = 客户未覆盖 且 pen(p) ≥ 30% 的品类
cross_sell = 100 × mean(缺口品类的 pen)
```
行业样本 < 3 家时退化为全盘口径。**为什么用同业渗透率而不是「有没有这个品类」**：
同业都买了说明需求被验证过，客户没买是覆盖问题，不是需求问题——这才是可攻的机会。

### 向上销售潜力 up_sell（权重 30%）
```
up_sell = 100 × (1 - 客户窗口消费 / 全盘 P75)
        + 15（配额使用率 ≥ 80% 时）
        + 8（资源数环比 > 20% 时，上限 100）
```

### 空白市场潜力 white_space（权重 20%）
```
场景型品类 = AI、大数据、容器、安全、灾备、PaaS
候选 = 客户未覆盖 且 同业渗透率落在 [20%, 65%] 的品类
white_space = 100 × mean(候选的 pen)
```
渗透率 < 20% 说明市场还没起来（教育成本高），> 65% 说明已红海（别人都买了，客户还不买多半有硬原因）。
**中间地带才是真正的空白机会。**

### 推荐意愿 advocacy（权重 20%）
```
有 NPS：advocacy = 50 + 45 × (NPS - 5)/5 - 25 × 升级比例
无 NPS：advocacy = 50 + 40 × 近 3 月情感均值 - 25 × 升级比例
都没有：advocacy = 45（中性）
```
推荐意愿高的客户，扩张型机会更容易推进（愿意给你引荐、愿意做案例），所以它进入排序而不是单独成一条机会。

## 2. 续约风险（防御维度，0~100）

```
risk = 100 × (0.40 × 合同临近度 + 0.25 × 活跃趋势 + 0.15 × 负面舆情 + 0.20 × 竞品强度)

合同临近度：≤60天 1.0｜≤90天 0.85｜≤180天 0.55｜≤365天 0.25｜>365天 0.10｜无日期 0.30
活跃趋势：  增速 ≤−15% → 0.80｜<0 → 0.55｜<15% → 0.30｜否则 0.10（沉睡客户至少 0.85）
负面舆情：  贝叶斯平滑后的负面占比 (neg+0.4)/(n+2)
竞品强度：  高 0.9｜中 0.6｜低 0.3｜无 0.1，取该客户所有信号的最大值
```
合同到期日缺失时，用签约周年推断下一个续约点并标注「估算」。

**平滑负面占比的原因**：3 条反馈里 2 条负面不该等于 67% 客户不满意。平滑后小样本会向 20% 收敛。

## 3. 综合排序

```
扩张型（交叉/扩容/ARPU/空白）：
  growth = 0.30×cross_sell + 0.30×up_sell + 0.20×white_space + 0.20×advocacy
  score  = growth × (1 - 0.40 × renewal_risk/100)
```
**为什么要乘风险折扣**：一个 90 分流失风险的客户，扩张机会再大也大概率打水漂。
先保住盘子再谈增量，这是 NA 经营的基本顺序。

```
必赢型（不参与折扣，直接用紧迫度/价值排序）：
  续约保卫 RENEW_DEFEND → score = renewal_risk（风险 ≥45 且到期 ≤180 天才生成）
  流失赢回 WINBACK      → score = 60 + {S:25, A:20, B:10, C:0}
  首单转化 ACQUIRE      → score = 45 + 35×min(1, 试用次数/3) + 10×advocacy/100
```

优先级：**A ≥ 70，B 50~70，C < 50**。

## 4. 六类机会与金额口径

| 类型 | 触发条件 | 金额公式 | 口径 |
|---|---|---|---|
| `RENEW_DEFEND` 续约保卫 | 有到期日，≤180 天且风险 ≥45 | 窗口消费 × risk/100 | **风险敞口**（非增量） |
| `WINBACK` 流失赢回 | 已流失 | 流失金额，缺失时取流失前窗口消费 ×50% | 预估赢回 |
| `ACQUIRE` 首单转化 | 潜在客户（有活跃无付费） | 同业该品类年中位 × 赢率 | 预估首单 |
| `XSELL` 交叉销售 | 存在 pen≥30% 的未覆盖品类 | 同业该品类**年中位** × 赢率（30%） | 预估年化 |
| `UP_CAPACITY` 容量扩容 | 使用率 ≥75% 或资源数环比 >20% | 主力品类窗口消费 × 30% | 预估年化 |
| `UP_ARPU` 用量提升 | 窗口消费 < 同层中位 × 75% | `min(同层中位缺口 × 50%, 现有消费 × 50%)` | 预估年化 |
| `WHITESPACE` 场景空白 | 存在渗透率 20%~65% 的未覆盖场景品类 | 同业该品类年中位 × 赢率 × 60% | 预估年化 |

**金额是排序工具，不是业绩承诺。** 报告里必须区分「增长型预估增量」与「风险敞口」两个口径，
不能加总成一个「机会总额」对外汇报——这是最容易出错的地方。

## 5. 每个客户的候选数量控制

- 交叉销售：最多取渗透率最高的 2 个品类
- 场景空白：最多 1 个
- 全局保留 top 30（`top_opps`），但**保证每个 S/A 客户至少保留 1 条**，避免高价值客户被长尾挤出

## 6. 判断依据怎么写（driver 字段）

必须包含「数据事实 + 对比基准」，不能写「客户有需求」这种废话。对比：

- ❌ 差：该客户有交叉销售机会
- ✅ 好：同行业 67% 的客户已采购数据库，该客户尚未覆盖（已覆盖 5/12 个品类）

- ❌ 差：客户可能流失
- ✅ 好：合同 29 天后到期，流失风险分 88，竞品信号强度 90%

driver 与 evidence 分开：`driver` 是结论性判断，`evidence` 是支撑数字（金额、占比、时序）。
报告与 CRM 两个字段都会带出去，销售看到这两句就知道该不该跟进。

## 7. 调参建议

| 场景 | 调整 |
|---|---|
| 团队更看重保盘子 | `opp_defend_penalty` 从 0.4 提到 0.6 |
| 赢率被历史数据校准过 | 把 `win_rate` 改成实际赢单率（按类型分别校准更准） |
| 客户数很少（<10） | 用 `tier_amount` 绝对阈值；`top_opps` 调小 |
| 只看 NA 客户 | 在 `input_dir` 前置过滤，或加 `field_overrides` 补 `na_flag` |

## 8. 证据分级（evidence_level / confidence）

这是报告可信度的关键。同一条「机会」，可能是铁证，也可能是猜的，读者必须一眼看出来——
否则销售会把「假设」当「事实」去申请资源，最后交付不了。

| 类型 | 默认等级 | 为什么 |
|---|---|---|
| `WINBACK` 流失赢回 | 事实 | 流失记录、流失金额来自系统 |
| `RENEW_DEFEND` 续约保卫 | 事实 | 合同到期日 + 风险分来自系统数据 |
| `RENEW_DEFEND`（到期日按签约周年估算） | **推断** | 没有真实合同日期，只能推算 |
| `ACQUIRE` 首单转化 | 推断 | 试用行为是事实，付费意愿是推断 |
| `UP_CAPACITY` 容量扩容 | 推断 | 使用率是事实，扩容需求是推断 |
| `UP_ARPU` 用量提升 | 推断 | 与同层差距是事实，能否补上是推断 |
| `XSELL` 交叉销售 | 假设 | 同业渗透率是事实，「这家会买」是假设 |
| `WHITESPACE` 场景空白 | 假设 | 行业低渗透是事实，适不适配是假设 |

置信度由「证据等级 + 机会分」合成：

- **高** = 事实 且 分数 ≥ 65
- **中** = 事实（分数不够）或 分数 ≥ 70（非事实）
- **低** = 其余

落地规则：

1. 报告与 CRM 都要带这两列，`假设` 类机会的下一步动作必须写成「先验证」而不是「直接报价」。
2. 证据构成比例（事实/推断/假设）要写进报告 01 节。假设占比高不是问题，
   **把它藏起来才是问题**——领导会以为 30 条机会都是铁证。
3. 不要把 `假设` 类金额与 `事实` 类金额加在一起当「可达成目标」。要加，就单独给一个
   「已验证机会」的小计。

## 9. 排名口径：声量与影响

痛点与机会一样存在「看起来重要」和「实际重要」的偏差。机会侧用评分排序即可，
痛点侧额外输出两套排名（`volume_rank` 按提及条数、`impact_rank` 按加权评分），
差值 `rank_gap` 为正说明「影响被低估」。

报告用 `rank_slope` 把它画出来。真话是：**只有少数情况下两者会明显背离**，
但恰恰是背离的那几条，决定了资源该往哪儿投。若两者完全一致，报告应直接说明
「本期声量即影响」，而不是硬编一个故事。
