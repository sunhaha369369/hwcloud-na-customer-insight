# 分层与画像模型（价值 × 生命周期 × 活跃度 → playbook）

## 1. 价值层级（M 维）

按**窗口消费额**排名，默认分位切分：

| 层级 | 分位 | 定位 | 资源投入 |
|---|---|---|---|
| **S 战略级** | ≥ 85% | 收入压舱石，通常是 NA 客户 | 专属团队、高层互访、联创 |
| **A 核心级** | 65% ~ 85% | 增长主力 | 客户成功 + 行业方案 |
| **B 成长级** | 35% ~ 65% | 有放量潜力 | 标准化方案 + 定期触达 |
| **C 长尾级** | < 35% | 维持与观察 | 自助 + 渠道 |

**客户数 < 10 家时不要用分位法**（会把 1 家客户直接判成 S）。改用绝对金额阈值：

```json
"tier_amount": { "S": 50000000, "A": 10000000, "B": 2000000 }
```

`na_flag=1` 但层级落在 B/C 的客户会被标记 `na_gap`，这是「NA 覆盖不足」的信号，
应在报告里单独点名，而不是直接提级。

## 2. 活跃度（E 维）

综合分 = 0.35×MAU + 0.20×登录次数 + 0.20×API 调用 + 0.15×资源数 + 0.10×配额使用率（均取近 3 月均值，
组内分位归一）。四档：**高活跃 ≥0.70 / 中活跃 ≥0.45 / 低活跃 ≥0.20 / 沉睡 <0.20**。

没有任何行为数据的客户标为「数据缺失」，不要判成沉睡——两者经营含义完全不同。

## 3. 生命周期（状态机，按优先级自上而下判定）

| 阶段 | 判定条件 |
|---|---|
| 已流失 | 流失表有记录，或窗口消费 = 0 且上期 > 0 |
| 潜在客户 | 窗口消费 = 0 但有行为/试用记录 |
| 新签爬坡期 | tenure ≤ 6 个月 |
| 流失预警 | 满足任一：连续 3 月下滑且累计 ≤ −15%；MAU 较前 3 月跌超 40%；竞品信号 ≥0.8 且增速为负；负面占比 ≥60% 且 90 天内到期 |
| 停滞期 | 增速 ≤ −10% |
| 成长期 | 增速 ≥ +15% |
| 成熟期 | 其余（−10% ~ +15%） |

tenure 取 `sign_date` 与首个有消费月份的较早者。

## 4. 画像标签与 playbook

标签 = 价值层级 × 活跃度，再用生命周期修正。每个标签绑定：策略主线、3~4 条具体动作、考核指标、触达节奏。

| 层级 | 活跃度 | 标签 | 策略主线 | 代表动作 | KPI | 节奏 |
|---|---|---|---|---|---|---|
| S | 高 | 压舱石·深度经营型 | 钱包份额 + 联合创新，防分割采购 | 高层季度互访、联创立项、预留实例锁 3 年、跨 BG 复制 | 钱包份额、NPS、续约率 | 月度健康度 + 季度高层 |
| S | 中 | 战略客户·场景渗透型 | 打进核心业务，先深后广 | 选 1 个业务域做架构评审、POC 换生产落地、对齐采购关键人 | 场景渗透数、生产负载占比 | 双周 |
| S | 低 | 战略客户·健康度急救型 | 先止血再谈扩张 | 48h TAM 上门诊断、问题清单与整改表、高管对齐 SLA | 活跃回升、重大工单归零 | 周度 |
| A | 高 | 核心客户·扩张型 | 品类扩张 + 容量承接 | 补 2 个高渗透品类、提前扩容报价、标杆案例共建 | 品类数、ARPU | 月度 |
| A | 中 | 核心客户·深耕型 | 做深现有场景，提升不可替代性 | 场景最佳实践 + 培训、TCO 优化换预算、推动第二部门立项 | ARPU、活跃度 | 月度 |
| A | 低 | 核心客户·唤醒型 | 重建使用习惯 | 盘点闲置资源、用量激励/试用新品类、CSM 回访 | 月活回升、资源数 | 双周 |
| B | 高 | 成长客户·加速型 | 用商务杠杆放大势头 | 打包方案 + 阶梯返点、上量承诺换价格、按需转包年 | 消费增速、包年占比 | 月度 |
| B | 中 | 成长客户·深耕型 | 做深主力场景并培育第二增长点 | 主力场景深度优化、推动第二部门上线、年度框架锁价 | ARPU、品类数 | 月度 |
| B | 低 | 成长客户·培育型 | 用标准化方案降低决策成本 | 目录化轻量方案 + 自助开通、线上训练营、季度关怀 | 激活率、首单转化 | 季度 |
| C | 高 | 长尾客户·自助增长型 | 低人力、靠体验与渠道 | 全自助开通计费、伙伴承接服务、自动化用量提醒 | 自助转化率、留存 | 季度 |
| C | 中 | 长尾客户·维持型 | 低成本维护关系 | 线上自助 + 季度关怀、行业模板、监控用量突变 | 留存率 | 季度 |
| C | 低 | 长尾客户·观察型 | 不投人力，等信号 | 纳入自动化培育池、用量突变触发升级、不投专属人力 | 升级转化数 | 半年度 |

**生命周期覆盖规则**

- `停滞期` / `流失预警`：标签加前缀「防御优先·」，动作列表强制置顶两条止血动作
  （48h 诊断根因、竞品对比 + 续约商务方案），再拼原有动作。
- `新签爬坡期`：标签加「·爬坡型」，动作置顶「30 天内完成上线验收与首个场景交付」。
- `已流失` / `潜在客户`：走独立 playbook（赢回 / 首单转化），不参与价值 × 活跃矩阵。
- `成长期` 且活跃度为低/沉睡：活跃档位**上调一档**再查矩阵。增速是前瞻信号，
  一个 100% 增长但当前月活还小的客户，不该被贴上「观察型」标签。

## 5. 输出字段（account_profile.csv）

`value_tier`、`value_pct`、`lifecycle`、`activity_level`、`activity_score`、`persona`、
`rfm`（R/F/M 各 0~5）、`rev_window`、`rev_prev`、`growth` + `growth_basis`、`active_months`、
`recency_months`、`mau_avg_3m`、`usage_avg_3m`、`sent_avg`、`neg_ratio`、`nps`、
`competitor_strength`、`days_to_renewal`、`renewal_risk`、`cross_sell`、`up_sell`、
`white_space`、`advocacy`、`strategy`、`actions`、`kpi`、`cadence`。

## 6. 使用注意

- 分位法 + 12 家客户的样本量，S 层只会有 1~2 家。若客户经理认为分层不合理，先看是不是
  **数据窗口内有大额一次性项目**——这会让 M 维虚高，建议改用「近 12 月 + 剔除非经常性收入」口径。
- 活跃度是相对分位，跨季度对比时若客户集合变化，档位会漂移。做趋势分析请锁定同一客户集合。
